# SolarCool — نظام مقارنة تبريد الألواح الشمسية

مشروع التخرج: نظام IoT متكامل بيقارن بين 3 ألواح شمسية — **مبرد بالمياه**،
**مبرد بالهواء**، و**بدون تبريد** — مع متابعة لحظية، وتخزين لكل قراءة،
وتحكم عن بعد في التبريد.

## البنية المعمارية

```
 الحساسات والمشغلات        MQTT              الباك اند              الداشبورد
+------------------+   نشر    الوسيط   اشتراك +--------------+  WebSocket  +-----------+
| ESP32            | ------> (أي وسيط ------> | Node.js      | ---------> | index.html|
|  حساسات حرارة    | قراءات  MQTT)           |  REST API    |           | (على      |
|  قياس قدرة INA219|        <------          |  WebSocket   | <--------- |  GitHub   |
|  حرارة الجو      | <------  أوامر          |  SQLite أو   |   REST    |  Pages)   |
|  متابعة البطارية | اشتراك                  |  Postgres    |           +-----------+
|  مروحة + طلمبة   |                         +--------------+
+------------------+
```

كل قراءة بتتخزن بتاريخها، فعندك سجل كامل للتحليل ورسوم يوم المناقشة،
مش مجرد شاشة لايف.

### ليه MQTT وباك اند حقيقي؟

- **MQTT هو المعيار الصناعي في IoT** — خفيف، pub/sub، وبيتحمل الشبكات الضعيفة.
- **مفصولين عن بعض**: الـ ESP32 والباك اند والداشبورد كل واحد مستقل، تقدر
  تغير أو توسع أي جزء لوحده.
- **قابل للتوسع**: لوح جديد أو حساس جديد أو حتى ESP32 تاني بيضاف بمفتاح أو
  رقم جهاز جديد بس، من غير أي تعديل في باقي النظام.
- **الأوامر محفوظة**: آخر سرعة للمروحة والطلمبة بترجع حتى لو الجهاز عمل ريستارت.

## تقسيم المشروع

| المسار | المحتوى |
|---|---|
| `index.html` | الداشبورد (ملف واحد، عربي/إنجليزي، رسوم لايف، تحكم في التبريد) |
| `firmware/solar_cooling_esp32/` | فيرموير الـ ESP32 (ينشر ويشترك عبر MQTT) |
| `backend/` | باك اند Node.js: استقبال MQTT، REST API، WebSocket، SQLite/Postgres |
| `broker/mosquitto.conf` | إعداد وسيط MQTT محلي |
| `docker-compose.yml` | تشغيل النظام كله محليًا بأمر واحد |
| `render.yaml` | نشر الباك اند مجانًا على Render بضغطة |

## مواضيع MQTT

| الموضوع | الاتجاه | المحتوى |
|---|---|---|
| `solarcool/<deviceId>/readings` | ESP32 ← الباك اند | لقطة JSON كاملة |
| `solarcool/<deviceId>/status` | ESP32 (وصية) | `online` / `offline` |
| `solarcool/<deviceId>/commands` | الباك اند ← ESP32 | سرعة المروحة والطلمبة (محفوظة) |

## الـ API

| المسار | الوظيفة |
|---|---|
| `GET /api/health` | حالة الخدمة والوسيط وقاعدة البيانات |
| `GET /api/devices` | الأجهزة المعروفة وآخر ظهور |
| `GET /api/latest` | أحدث لقطة كاملة |
| `GET /api/readings` | السجل الخام للرسوم والتحليل |
| `GET /api/stats` | متوسطات وقِمم وطاقة (واط·ساعة) لكل لوح |
| `POST /api/commands` | إرسال سرعة المروحة/الطلمبة للـ ESP32 |
| `WS /ws` | بث حي للقراءات والحالة والأوامر |

## التشغيل محليًا (١٠ دقايق)

```bash
# 1. حسابات الوسيط والشهادات (مرة واحدة، شوف broker/README.md)
# 2. شغّل النظام
MQTT_PASSWORD=... OPERATOR_TOKEN=... COMMAND_KEY=... docker compose up
```

الداشبورد: افتح `index.html` واملى `restUrl` و `wsUrl` و `operatorToken`.
الخطوات كاملة في [docs/GO-LIVE.md](docs/GO-LIVE.md).

## النشر مجانًا

1. **الوسيط**: اعمل كلاستر مجاني على HiveMQ Cloud أو EMQX Serverless
   (أو خلي Mosquitto على Raspberry Pi جنب المشروع).
2. **الباك اند**: Render ← New ← Blueprint ← اختار الريبو — ملف `render.yaml`
   بيجهز الخدمة وقاعدة Postgres المجانية لوحده؛ املى متغيرات MQTT
   زائد `OPERATOR_TOKEN` و `COMMAND_KEY`.
3. **الداشبورد**: جاهزة على GitHub Pages. حط لينك الباك اند في `index.html`
   واعمل كوميت.

ملحوظة: الخطة المجانية في Render بتنام لو مفيش استخدام. الـ ESP32 بيفضل
يبعت والباك اند بيلحق أول ما يصحى. عشان عرض لايف متواصل، شغّل النظام على
Raspberry Pi بأمر `docker compose up`.

## التوصيلات (الافتراضي)

| القطعة | طرف الـ ESP32 |
|---|---|
| 3 حساسات DS18B20 (خط واحد، مقاومة 4.7kΩ) | GPIO 4 |
| حساس الجو DHT22 | GPIO 15 |
| 3 حساسات INA219 (عناوين 0x40 / 0x41 / 0x44) | GPIO 21 (SDA)، 22 (SCL) |
| مقسم جهد البطارية (100k / 27k) | GPIO 34 |
| بوابة موسفت المروحة (PWM) | GPIO 25 |
| بوابة موسفت الطلمبة (PWM) | GPIO 26 |

## الوضع التجريبي

من غير لينك الباك اند، الداشبورد بتولّد بيانات محاكاة واقعية (اللوح بدون
تبريد أسخن، والسلايدرز بتأثر في الحرارة فعلًا)، فتقدر تتمرن على العرض كامل
قبل ما الهاردوير يشتغل.

## الأمان (مبني وشغال افتراضيًا)

- **وسيط خاص**: مفيش دخول مجهول، TLS على 8883، وصلاحيات لكل جهاز — الجهاز
  ينشر قراءاته بس ويقرا أوامره بس. الإعداد في [broker/README.md](broker/README.md).
- **توكن المشغّل**: مسار الأوامر `POST /api/commands` محتاج Bearer token.
- **قفل أمان في الجهاز**: الـ ESP32 يتجاهل أي أمر من غير `COMMAND_KEY`،
  والمخرجات متظبوطة على حد أقصى (`FAN_MAX_PCT` / `PUMP_MAX_PCT`).

الوسطاء العموميين المفتوحين للتطوير المبدئي بس — أبدًا مش للعرض.
